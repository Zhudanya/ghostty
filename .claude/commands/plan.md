# /plan

分析需求并创建实施计划，**不写任何代码**，直到用户确认。

## 执行流程
1. **需求重述** — 用中文清晰重述需求，明确 scope
2. **代码定位** — 搜索相关文件，给出 `文件:行号`
3. **cmux 参考** — 检查 cmux 是否有对应功能实现（`../cmux/Sources/`），提取可借鉴点
4. **影响分析** — 列出受影响的模块/平台/调用链
5. **分步方案** — 按修改顺序列出每一步（改什么、怎么改、为什么）
6. **风险评估** — HIGH/MEDIUM/LOW，特别关注跨平台影响
7. **等待确认** — 用户说"确认"后才进入编码阶段
